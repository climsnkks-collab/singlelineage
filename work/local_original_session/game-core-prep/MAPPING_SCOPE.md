# L1J 데이터의 클래식 대응 범위

2026-10-26. 비교 기준은 이미 분석한 클래식 클라이언트 **26.09.29.2001**과 로컬 보관된 **l1j-en/classic(2009년 미국 클라이언트 계열)**이다. 기존 공식 자료는 2026-10-09 저장본을 사용했다. 이번에는 파일만 읽었으며 게임·서버·L1J를 실행하지 않았다. 아래 판정은 자료 대응 범위이고 실제 플레이 동등성 판정이 아니다.

**그대로 재사용할 근거가 가장 분명한 것은 말하는 섬 map0의 번호와 정수 좌표계다. NPC·아이템 번호는 대응표가 필요하고, gfx도 일부만 같다. “몇 번 이하까지 모두 같다”는 연속 구간은 확인되지 않았다.** 클라이언트 내부 데이터 → 저장된 공개 공식 정보 → L1J 순서로 채우며, L1J의 능력치·보상·성장값은 출처를 밝힌 로컬 정책으로 구분해야 한다.

근거 경로를 줄여 쓴다. `l1jdb_m10.sql`은 `D:/SingleLineageRef/l1j-en-classic/db/l1jdb_m10.sql`, `src/`도 같은 L1J 루트 기준이다. `native-dump-v1.jsonl`은 `work/source_game_data/native-dump-v1.jsonl`, `all-rows.csv`는 `work/monster_level_comparison/analysis/all-rows.csv`, `region.jsonc`는 `work/local_resource_provider/assets/data/region.jsonc`다. 아래 `파일:줄`은 이 원문과 기존 분석 자료의 줄 번호다.

## 2. M1 후보: 말하는 섬 마을 바깥 초원(map0)

**현재 좌표32578,32946에서 y가 작은 쪽의 초원 구역**을 추천한다. 해당 좌표는 클래식 마을 경계 안이며 기존 actual176 기록도 map0에서32577,32946→32578,32946의 서버·클라이언트 일치를 남겼다(`region.jsonc:3`, `work/local_original_session/implementation-2/npc-motion-goal/HANDOFF.md:1610`). map0 자원은 기존 분석에 있고, 현재 region의 맵 번호는 현재 catalog의 맵 경로와 대응한다(`work/asset_link_audit_20261007/map/report.md:20`, `:24`). 다른 맵으로 옮기지 않고 기존 map0 연결을 이어갈 수 있다는 점이 유리하다.

## 3. 대응표를 만드는 가장 싼 방법

전량 변환부터 하지 말고 위 네 종과 실제 드롭에 필요한 아이템만 기존 `native-dump-v1.jsonl`·`all-rows.csv`·L1J SQL에서 뽑아 대응시킨다. NPC는 **공통 이름 토큰($59 등)으로 후보를 묶고 → 공식 이름·레벨·출현 지역으로 변종을 구별하고 → 클래식 f2와 SPR 이름으로 외형을 선택**한다. 토큰도 버전 공통이라고 전제하지 말고 매칭한 항목에서 이름을 확인한다. 아이템은 이름 토큰·종류·등급을 확인해 클래식 ID로 바꾼다. 각 행에 양쪽 ID·근거·확정/후보를 남기고 중복 후보는 억지로 하나로 합치지 않는다. 스폰 좌표는 map0 정수 좌표를 유지하되 기존 클래식 통행 해석을 사용하고, 속도는 클래식 SPR을 우선한다. 드롭 구성은 현재 클라이언트/공식 목록을 유지하며 HP·보상 EXP·확률·수량·성장 곡선의 빈칸만 L1J 출처와 로컬 정책 표시를 붙인다. 새 추출기나 전수 검증기를 만드는 것보다 이 범위의 짧은 수작업 대응이 가장 싸다.
