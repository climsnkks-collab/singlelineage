# 요청·틱 경로 반복 비용 감사

2026-10-26 읽기 전용 정적 감사. 작성 파일은 이 문서 하나이며 제품 코드·설정·저장·큐는 수정하지 않았다. 게임·서버·벤치마크·제품 모듈 import·시험은 실행하지 않았다.

**현재 남은 주요 반복 비용은 공격/Use/Death·Remove 등의 고정 evidence 재읽기, 이동마다 저장 파일 반복 읽기와 fsync, 공용 asyncio 루프에서의 관측·JSON 출판이다.** 반면 현재 `NativeOwner.verify_sources`는 실행 파일 전체 해시가 아니고, `inventory._source`와 `inventory_store._source`에는 캐시가 있다. 이들을 과거 구현과 혼동하면 비용을 크게 잘못 계산한다.

## 1. 판정 범위·호출 수 읽는 법

- 대상은 `tools/local_original_session/`의 Python과 자체 native 코드다. `rg`로 파일 읽기·해시·쓰기·fsync·sleep/wait 및 그 caller를 찾고, 실행 연결의 원문을 확인했다. vendored Detours와 외부 의존 구현 전체의 비용은 이 목록에 포함하지 않는다.
- **줄번호와 바이트 수는 감사 중 관찰값**이다. broker/launcher/inventory/observe/NPC/item 파일을 다른 작업자가 동시에 수정하고 있으므로 원자적 소스 스냅샷이나 변경 후 상태의 보장은 아니다. 함수 이름과 조건을 함께 찾는다. 파일을 동결하거나 복사·해시 전수 대조하지 않았다.
- 아래 Python 파일 경로는 별도 표시가 없으면 `tools/local_original_session/` 기준이다. `A → B`는 정적 caller 관계이고 실제 실행 성공의 뜻이 아니다. 기능 플래그·선정 Source에 따라 꺼지는 경로는 조건부로 표시했다.
- 읽기량은 해당 파일들의 당시 크기 합 또는 코드의 상한이다. **OS 파일 캐시 적중 여부·밀리초 지연·CPU 점유·스토리지 flush 시간은 미측정**이다. 파일 열기/읽기/해시/JSON 파싱과 경로 검사 수를 예상 비용으로 사용한다. 작은 파일도 동기 syscall·디렉터리 검사·파싱 비용이 있다.
- `C`=수신 청크 수, `F`=디코딩 요청 프레임 수, `R`=실제 송신 프레임 수. 일반 경로의 `_sample` 기본 횟수는 **C + F + 2R**: `_serve` 청크 checkpoint(4346), 프레임 checkpoint(4356), `_send` wire별 pre-write checkpoint(3666)와 post-drain owner(3853). 초기 admit·기능 owner·종료·idle poll·queue 대기는 추가다. 여러 응답을 한 `_world_send` chunk에 넣어도 `_send`는 wire마다 검사한다.
- `WorldRuntime.tick_once:69`는 scheduler와 hook을 공용 world lock 안에서 실행한다. `_serve`도 row operation lock 안에서 처리한다. 그 안의 동기 파일·메모리 I/O는 해당 coroutine뿐 아니라 같은 이벤트 루프의 다른 요청·틱도 늦출 수 있다. 정확한 지연은 실측 전 UNKNOWN이다.

## 7. 재사용 근거·미확인

- [기존 관측 atomic 수정 결과](../integration-1/observation-atomic-fix/RESULT.md) 5줄: 관측 output-only도 write/flush/fsync/replace를 시도하며 공유위반 시 defer하는 계약이다. “관측이므로 메모리만 쓴다”로 해석하지 않았다.
- [기존 drain/current API](../shared-api/npc-postreply-drain-current/API.md) 11줄, [pending removal freshness 계약](../shared-api/comp01-actual265-pending-removal-current-sample-v1/API.md) 34줄: sample freshness **250ms**와 drain **2초**는 별개다. 과거 DRAIN_TIMEOUT의 정확 원인 미확정을 이번 정적 목록으로 확정하지 않았다.
- [기존 cold dependency cache 계약](../shared-api/book-cold-explicit-dependencies/API.md) 14줄: 첫 로딩 후 선택·metadata cache 개념을 재사용했다. 다른 기능의 정적 evidence 캐시 후보가 기존 실행 PASS를 승계한다는 의미는 아니다.
