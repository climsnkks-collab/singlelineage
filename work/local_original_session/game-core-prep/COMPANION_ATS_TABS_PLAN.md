# 동료 ATS: 탭 편집으로 회복·공격·버프 나눠 세팅 (계획, 2026-10-30)

## 목표
동료 ATS 창(SLCompATS, DLL이 만든 창)의 탭을 DLL이 고쳐서, 마법을 **회복 / 공격 / 버프** 세 곳에 끌어다 놓기만 하면 동료가 알아서 쓰게 한다.
- 버프·공격 칸은 원작 판정 그대로: 버프 = 마법 표 f13에 9, 공격 순차·조건 = f13에 10 (원본 0x8F7AC0 / 0x8E6E50).
- 원작에 없는 **회복 칸**을 동료 전용으로 새로 둔다. 힐 계열은 여기에만 들어간다.

## 후킹 방식 (기존에 되는 것만)
NC 보호로 인라인 훅은 못 쓴다. 지금 DLL이 이미 쓰는 세 가지만 쓴다.
1. 원본 함수 호출 (CSB 로드 0xA56F30, addChild/removeFromParent, setPosition, setVisible, 버튼 콜백 0xA5C1E0)
2. 콜백 교체 (탭 버튼·Save·칸 오른쪽 클릭)
3. UI 노드 조작 (숨기기, 옮기기, 다른 CSB 조각 붙이기)

## 화면 구성 (사용자 결정 2026-10-30)
현재 탭: 버프 / 전투 / 옵션 / 도움말.

- **버프 탭**: 지금 그대로 (회복 물약 2+2, 기능 아이템 6, 버프 마법 18칸). 물약 칸도 여기 그대로 둔다. 버프 마법 칸만 f13=9 필터 추가.
- **전투 탭**: 지금 그대로 (공격 순차 8칸, 공격 조건 8칸). f13=10 필터 추가. 펼쳐진 조건 목록은 이미 접음.
- **옵션 탭**: 지금 그대로.
- **도움말 탭 → "회복" 탭으로 바꿈**: 탭 버튼 글자를 "회복"으로 바꾸고 도움말 내용은 숨긴다. 그 자리에 ATSLayout.csb를 한 번 더 읽어 `Root.Combat.02`(칸 + 조건 선택 + % 입력) 조각을 떼어 붙인다.
  - **HP 회복 칸 4개**: 마법(드래그) + 조건 "HP n% 이하". 대상 선택은 없다.
  - **상태 회복 칸 2개**: 큐어 포이즌·리무브 커스 전용. % 입력 없이 독·저주가 걸린 대상이 있으면 쓴다.
  - 위에서부터 우선순위. 조건 맞는 첫 칸을 쓴다.
- **탭 순서 (사용자 결정)**: 왼쪽부터 버프 / 공격 / 회복 / 옵션.
  - 원래 버튼 자리는 x 467.5 / 556.5 / 645.5 / 734.5이다(glfw73 트리 scene_bounds).
  - `Bt_Help`(회복)와 `Bt_Option`은 같은 `Root.Tab` 아래에 있으니 서로의 원래 위치값만 맞바꾼다(setPosition vt 0x80).
  - 탭 콜백은 페이지에 묶여 있어 자리가 바뀌어도 그대로 동작한다.

### 회복 칸 레이아웃: 공격 조건 칸(`Root.Combat.02`) 재사용
공격 조건 칸 한 줄은 `Slot_0n` = 마법 칸(`Slot`) + 조건 풀다운(`Pulldown_Menu`) + 수치 입력(`Bg_TextField.TextField`)이고, 8줄이 있다. 회복 칸에 필요한 구성이 이미 다 들어 있으니 이걸 그대로 쓴다.
- ATSLayout.csb를 한 번 더 읽어 `Root.Combat.02`만 떼어 `Root.Help` 안에 붙인다. 공격 순차(`Combat.01`)는 붙이지 않는다.
- 1~4줄은 HP 회복 칸이다. 조건은 "HP n% 이하"로 고정한다(사용자 결정).
  - % 숫자 입력칸(`Bg_TextField`)은 숨긴다.
  - 풀다운은 **10% 단위**로 고른다(사용자 결정). 목록은 10%~90% 9개이고, 글자는 "HP 50% 이하" 꼴이다. 기본값은 50%.
  - 원작 목록에는 칸(Panel)이 6개뿐이다. 모자란 3개는 숨긴 5~8줄의 목록 칸을 옮겨 쓴다(removeFromParent → ListView addChild → 0x650 갱신).
- 5~6줄은 상태 회복 칸이다. 풀다운과 수치 입력을 숨기고 마법 칸만 남긴다.
- 7~8줄은 숨긴다.
- 제목 `Tx_Sub01`은 "회복"으로 바꾼다.

### 도움말 탭 후킹: 이미 있는 것 재사용 (새로 만들지 말 것)
예전 데이브레이크 작업에서 도움말 탭은 이미 후킹해 실제로 동작을 확인했다. 그대로 가져다 쓴다.
- 탭 버튼 콜백 교체: `Root.Tab.Bt_Help`+0x4f0에 `0xA5C1E0`으로 함수객체를 넣는 방식이다(`companion_bridge_nopatch.hpp:668~690`). companion5 창에서는 이미 `BindButton` → `SelectTab(3)`으로 묶여 있다(`companion5_ats_window.hpp:705`).
- 탭 글자 바꾸기: `Root.Tab.Bt_Help.Tx_Help`에 Snapshot(0xBF9F90) + `SetText`를 쓴다(`companion_bridge_nopatch.hpp:665`, `AtsText`). 화면에 "동료: SoloMage"가 표시되는 것까지 확인했다. 다만 탭 폭 때문에 글자가 잘렸으니 "회복" 두 글자로 쓴다.
- 페이지 전환: `SelectTab`의 `Root.Help` 보이기/숨기기를 그대로 쓴다.
- 새로 할 일은 세 가지뿐이다. Tx_Help 글자를 "회복"으로 바꾸고, `Root.Help` 안의 도움말 글을 숨기고, 그 자리에 Combat.02 조각을 붙인다.

## 회복 대상 (사용자 결정)
- 나·주인·다른 동료를 가리지 않는다. 같은 맵·사거리·시야 안의 **일행 전원**(자신, 주인, 주인의 다른 동료) 중 칸 조건(HP n% 이하)에 맞는 사람에게 쓴다.
- 여럿이 맞으면 HP 비율이 가장 낮은 쪽부터.
- 동료가 나중에 여럿이 될 것을 감안해, 후보 목록은 "자신 + 주인 + 주인의 다른 동료 전원"으로 처음부터 만든다(지금 동료 1명이어도 같은 코드).
- 상태 회복 칸도 같은 후보에서 독·저주가 걸린 사람을 고른다.

## 칸 필터 (DLL + 서버 둘 다)
- 서버가 view의 `learned_spells`마다 `slot_traits`(f13 값 목록)와 `heal_kind`(회복 마법 여부)를 같이 보낸다. 출처는 `work/all_table_semantics/spell_token/spell-records.json`.
- DLL `DraftSpell`: 버프 칸은 9, 공격 칸은 10, 회복 칸은 heal_kind만 받는다. 안 맞으면 놓아도 안 들어가고 상태는 `ATS_WINDOW_SPELL_KIND_REFUSED`.
- 서버 저장 검사(`_ats_window_check_learned`)도 같은 규칙으로 거절한다.
- 회복 마법 목록: HP 회복 칸 = 힐·익스트라 힐·그레이터 힐, 상태 회복 칸 = 큐어 포이즌·리무브 커스(동료 지원분, `world_feature_companion.py:140`).

## 저장
- 버프·공격 칸은 지금처럼 원본 ATS blob(ats_config_codec)에 저장한다.
- 회복 칸은 원본 형식에 자리가 없으니 동료 저장 옆에 LOCAL 필드 `heal_slots`로 둔다(Save delta에 `heal_slots` 추가).
- 이전 저장 옮기기는 하지 않는다. 공격 칸에 들어 있는 힐은 지금처럼 공격 칸 규칙으로 계속 동작한다. 회복 칸은 기존 동작에 더해지는 기능이다.
- 회복 칸 저장 형식: `heal_slots` 6개. 0~3번은 `{spell_row|null, percent∈{10..90, 10단위}}`, 4~5번은 `{spell_row|null}`.

## 동료 AI
- `world_feature_companion.py`의 회복 판단을 battle_slots가 아닌 `heal_slots`에서 읽는다. 공격·버프 로직은 그대로.
- 판단 순서를 바꾼다. 지금은 버프 갱신 → 공격 칸(힐 포함)이라 피가 빠져도 버프부터 건다(`world_feature_companion.py:609~669`). 바꾼 뒤: HP 회복 칸 → 상태 회복 칸 → 버프 갱신 → 공격 순차/조건.
- 후보는 위 "회복 대상" 규칙(일행 전원, HP 비율 낮은 순).

## 정한 것 (사용자 2026-10-30)
1. 회복 탭 자리: 도움말 탭을 바꾼다. 옵션 탭은 그대로.
2. 회복 대상: 선택지 없음. 자신·주인·(나중에 늘어날) 다른 동료 중 HP 조건에 맞는 사람.
3. 상태 회복 칸 2개를 따로 둔다(큐어 포이즌·리무브 커스).
4. 회복 물약 칸은 버프 탭에 그대로.

## 빈 곳: 공격 조건 칸 풀다운·% 미연결 (같이 채움)
- 원작 조건 풀다운은 6개다: HP(이상), HP(이하), MP(이상), MP(이하), 시간, 누적(`ATS_COMPANION_TOGGLE_DESIGN.md` f1 1~6 표, `ats-evidence/resource_findings.md:23`).
  - CSB에 적힌 기본 글자는 8줄 모두 "HP(이상)"이다.
  - 원작은 초기화할 때 저장된 조건으로 글자를 다시 쓴다. f1=0이면 빈 글자다.
- 지금 동료 창은 원작 초기화를 부르지 않는다. DLL과 서버 모두 조건 값을 다루지 않는다(`companion5_ats_window.hpp`에 조건 코드가 없다).
  - 그래서 화면의 "HP(이상)"는 CSB 글자가 그대로 남은 것이다(glfw84 `after-companion-spell-to-conditional.png`).
  - 조건 칸에 놓은 마법은 조건 없이 저장되고, 동료는 조건 없이 쓴다. 조건 목록이 비면 항상 통과한다(`world_feature_companion.py:654`).
- **사용자 결정 (2026-10-30)**: 당장은 공격 마법을 쓰지 않으니 공격 조건 칸은 그대로 둔다. 회복 칸만 "HP(이하)"로 고정해서 만든다.
- 나중에 할 것: "주변 적 n마리 이상" 같은 원작에 없는 조건을 공격 조건에 추가한다. 이때 원작 6개 풀다운·수치 입력도 같이 연결한다(DEFERRED_BACKLOG.md).

## 남은 것
- 칸 필터(f13 9/10) 적용 여부는 사용자가 아직 정하는 중. 정해지기 전에는 버프·공격 칸 필터는 넣지 않고, 회복 칸만 회복 마법으로 받는다.
