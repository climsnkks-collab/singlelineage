# 상태 변화 → 클래식 클라이언트 표시 전수 대조

조사일: 2026-10-30. 범위는 현재 작업트리의 서버 상태 생산자·등록 훅·송신 투영과 보존된 고정 클래식 분석이다. **읽기와 이 문서 작성만 수행했다. 코드 수정·게임·봇·서버 실행·현재 화면 검증은 하지 않았다.** 다른 작업자가 코드를 수정 중이므로 아래 줄 번호는 조사 시점 기준이며, 실행 중인 서버의 소스 조합을 확정한 보고서가 아니다.

## 읽는 법과 근거 경계

- 경로 약칭: `T/` = `tools/local_original_session/`, `G/` = `work/local_original_session/game-core-prep/`, `R/` = `work/local_server_rea_20261016/`, `A/` = `work/all_table_semantics/`, `D/` = `work/asset_data_analysis/`, `L/` = `D:/SingleLineageRef/l1j-en-classic/src/l1j/server/server/`. 모두 프로젝트 루트 기준이며 `:숫자`는 실제 파일 줄이다.
- opcode는 16진수, `fN`은 해당 메시지의 protobuf 필드다. 서로 다른 메시지의 같은 번호는 같은 의미가 아니다. 주소는 별도 표기가 없으면 원 분석 carrier의 RVA다.
- 고정 원문에도 계보가 둘 있다. CONTROL `9ffc24fe…b7af`와 UI/legacy 분석 carrier `c8228383…01a9`를 구분한다. 현재 packed 디스크·실행 메모리·전체 자원 동일성은 이 조사에서 재검증하지 않았다. 원 계보와 한계: `G/SELFINFO_FIELDS_EVIDENCE.md:9`, `G/CHAT_EVIDENCE.md:20`, `G/QUEST_DISPLAY_EVIDENCE.md:62`. 과거 문서의 당시 구현 상태보다 현재 T/코드를 우선했다.
- 근거 수준: **A** = 원 필드→구체적 소비자 정적 연결, **B** = 원 등록·타입/스키마 또는 자원은 확인했으나 정상 발급값·끝단 소비 미확인, **C** = 서버/자원 대응을 이용한 명시적 추론, **U** = 클래식 계약 미확인. A도 현재 화면 성공을 뜻하지 않는다.
- 난이도: **낮음** = 기존 확인된 codec/송신 접점의 연결, **중간** = 대상·수명·중첩·해제·복원 동시 연결, **높음** = 클래식 필드/소비/정상값 추가 확보 필요. 실제 작업량 확정 견적은 아니다.
- 표의 ‘누락’은 해당 생산자→소비자 범위의 코드 확인이다. ‘미확인’은 추측으로 패킷을 만들어야 한다는 뜻이 아니다. 채팅 번호·아이콘·색·입력 잠금·해제값을 확인하지 못한 상태는 그대로 미확인이다. 원본에 매 상태마다 모든 종류의 피드백이 반드시 존재한다고 가정하지 않았다.
