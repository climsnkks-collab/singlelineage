# 리니지 클래식 공식·공략 자료 지도 (몬스터·드롭·아이템)

조사일 2026-10-27 KST. 목적은 **어디서 무엇을 공식으로 확인할 수 있는지** 파악하는 것이다. 데이터 표(`tools/local_original_session/data/m1/*.json`)와 코드는 바꾸지 않았다. 게임 실행, 로그인, 유료 자료 접근은 하지 않았고 모두 익명 GET이다. 원문 응답은 세션 scratchpad에 임시로만 저장했으므로 정식 근거로 쓰려면 아래 4장 방법으로 다시 받아 SHA와 함께 보관해야 한다.

표기: **확인** = 응답 원문으로 직접 본 것. **추정** = 표본 대조에서 나온 해석.

## 0. 요약

- 공식 사이트에서 얻을 수 있는 것: 몬스터 레벨·크기·언데드/데몬·출현 지역·드롭 **목록**, 아이템 피해(작은/큰)·AC·무게·착용 직업·재질·안전 인챈트·옵션·세트 효과·회복량 범위, 마법 소모 MP·학습 레벨.
- 공식에 **없는 것**: 몬스터 HP·MP·AC·MR·경험치·STR·선공 여부, 드롭 **확률·수량**, 아데나 양. 업데이트 노트도 "드롭률 상향"처럼 말로만 쓰고 숫자는 없다.
- 표본 대조: M1 몬스터 4종의 레벨·드롭 구성은 전부 일치. 테스트 기사 장비 7종은 피해·AC·무게·직업·안전 인챈트까지 **차이 0**. M1 아이템 40개 전체로 넓히면 **9개 아이템, 10개 값**이 다르다(양손검 피해 17/21 → 공식 14/16, 물약 무게, 나무방패 무게 등).
- 새로 확인한 것: 클라이언트 `item.bin` f10은 **무게×1000**이다(공식 무게 = floor(f10/1000), 40/40 일치). 프로젝트 items.json은 이걸 "의미 미확정"으로 두고 L1J 무게를 써서 5개가 어긋난다. f13 = 착용 가능 직업(31/31 일치, 추정), f9 = 재질 코드(추정), f24 = 상점 기본가(7/8 일치, 추정).

## 2. 공식 출처 (엔씨 리니지 클래식, lineageclassic.plaync.com)

모두 리니지 클래식 전용 도메인과 `linclassic` 서비스 코드라서 리마스터나 리니지M과 섞이지 않는다.

### 2-1. 사전 (게임 정보 DB) — 가장 쓸모 있음

페이지: https://lineageclassic.plaync.com/ko-kr/info/item · /info/monster · /info/spell. 화면은 JS가 아래 JSON API를 불러서 그린다(로그인 불필요).

| 사전 | 목록 API | 상세 API | 2026-10-27 항목 수 | 들어 있는 정보 |
|---|---|---|---:|---|
| 몬스터 | `https://api-goats.plaync.com/linclassic/v2.0/dict/search/monster?searchKeyword=&locale=ko-KR&page=N&size=50` | `.../v2.0/game/monster/{id}?locale=ko-KR` | **366** (10-09엔 351) | 이름, 아이콘, **레벨**, `big`(큰/작은 몬스터), `damageable`(손상 몬스터 표시), `undead`/데몬 속성(해당 몬스터만), 출현 지역, **드롭 목록**(무기·방어구·기타 분류, 아이템 ID와 이름. 저주 등급은 "저주받은 ~" 이름으로 구분) |

- 목록 API는 `size`가 최대 50으로 잘린다(700을 줘도 50개). 필터 파라미터는 사이트 JS(itemdict.js)에 `grades, classes, category1, category2, aligns, elementals, forms, region1~3, exact`가 있다. `elementals`가 있으므로 몬스터 약점 속성도 공식 필터로 뽑을 수 있을 가능성이 있다(**추정, 미시험**).
- 아이템 `enchantLevel` 파라미터를 주면 `extra`가 채워진다. 장검 +6 → sdam 8+6, ldam 12+6.
- 상세 응답의 `oneHanded`는 활·양손검에서 `true`라서 이름과 반대로 "양손 여부"로 보인다(**추정**). 그대로 옮기지 말고 options의 "양손"을 기준으로 삼는다.
- 클라이언트 덤프(26.09.29)와 ID 겹침: 아이템 566/610, 몬스터 343/366(나머지 몬스터는 npc.bin에 없음), 마법 110/110. 공식 쪽에만 있는 것은 덤프 이후 업데이트(10/21 해적섬 등)로 추정한다.
- **없는 정보**: 몬스터 HP·MP·AC·MR·EXP·STR·DEX·선공·이동/공격 속도, 드롭 확률·수량·아데나 양, 아이템 가격.

### 2-2. 가이드북

- 목차 API: `https://lineageclassic.plaync.com/api/v2/lineageclassic/categories?gwLocale=ko_KR` → 대분류 12개, 소분류 52개(초보자·클래스·마법·퀘스트·마을·아이템·전투·사냥터·컨텐츠·커뮤니티·주요 시스템·PC방). 각 노드에 수정 시각이 있다.
- 본문 API: `https://lineageclassic.plaync.com/api/v2/lineageclassic/guide/{제목}?gwLocale=ko_KR` (예: 무기, 방어구, 스탯, 기사, 변신, 서먼 몬스터, 펫, 마을 소개). `아이템 소개`, `사냥터`, `시간제 던전`은 이 경로로 JSON이 안 나왔다(제목이 다를 수 있음, 미확인).
- 내용은 대부분 설명문이다. 숫자 표가 있는 곳: **스탯**(클래스별 기본 스탯과 보너스 포인트. 기사 16/12/14/8/9/12 + 4, Str 최대 20), 변신 목록, 서먼 몬스터 종류, 던전 보스·주요 보상, 레벨 퀘스트. 무기 문서에는 "무기 기본 +6 안전, 뼈 재질은 실패 확률", "둔기·지팡이는 손상 안 됨", "창 2칸 공격" 같은 규칙이 있다.
- 몬스터 능력치 표나 드롭 확률은 없다.

## 5. 체계적 수집 방법 제안

### 우선순위

1. **공식 사전 JSON API (주 출처)**. robots.txt 허용, 로그인 불필요.
   - 목록: 아이템 13쪽, 몬스터 8쪽, 마법 3쪽(size=50) = 24요청.
   - 상세: 아이템 610 + 몬스터 366 + 마법 110 = 1,086요청. 0.2~0.5초 간격이면 10분 안쪽.
   - 인챈트 extra가 필요하면 무기·방어구에 `enchantLevel=1..enchantLevelMax`를 더 받는다(최대 약 3,000~4,000요청. 선형인지 몇 개로 먼저 확인하고 줄인다).
   - 원문을 응답별 URL·조회 시각·SHA256과 함께 `work/` 아래에 저장한다(기존 `official_monster_research` 방식과 같게).
   - 조인 키: 공식 아이템 ID = 클라이언트 item.bin ID, 공식 몬스터 ID = npc.bin ID(이름이 같은 다른 ID가 있으니 ID로만 맞춘다). 드롭 등급은 이름 앞의 "저주받은"으로 구분되며, 클라이언트 f21의 등급과 대조한다.
2. **인벤 DB HTML (보조 출처)**: 공식에 없는 선공·약점·판매 NPC·가격·제작·인챈트 표만 가져온다. 몬스터 `/db/monster/{공식ID+1}` 약 366쪽, 아이템 `/db/item/{ID}` 약 610쪽. HTML 구조는 `크기/등급/약점/특징/선공/손상/출현 정보/드랍 아이템` 라벨 뒤 값 순서라서 라벨 기준으로 파싱하면 된다. robots.txt는 일반 크롤러를 허용(Wget만 차단). ID+1 규칙은 표본 5건이므로 수집 때 이름으로 검증한다.
3. **업데이트 노트 API**: 62개 본문을 받아 "드롭/경험치/무게/세트/분류 변경" 이력표로 만든다. 숫자는 없으므로 어느 값이 언제 바뀌었는지 표시용이다.
