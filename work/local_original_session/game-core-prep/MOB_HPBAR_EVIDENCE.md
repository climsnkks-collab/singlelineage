# 몹 머리 위 HP 바 — 기존 근거와 화면 실험 후보

2026-10-26 · 기존 산출물·지정 L1J 소스의 읽기 전용 대조. 변경은 이 문서 하나다. 새 역분석·게임·서버·패킷 송신·원본/저장 변경은 수행하지 않았다.

## 결론

**일반 몹을 선택하거나 때렸을 때 머리 위 HP 바를 갱신하는 클래식의 확정된 송신 계약은 아직 없다.** [M1_REWARD_PACKETS.md](M1_REWARD_PACKETS.md)의 4EC8 업무 의미 UNKNOWN 판정은 유지한다. 다만 실험 우선순위는 **4F1A의 확인된 HP 디버그 텍스트 → 같은 패킷 f2의 비율 가설 → 4EC8의 익명 필드 가설**로 구분할 수 있다.

`4F1A`에는 MonsterActorHud의 실제 current/max 텍스트 소비가 있다. 이 사실은 일반 HP 바를 입증하지 않지만, 업무 의미가 미확정인 `4EC8`보다 값 변화와 화면 반응을 대조할 직접 근거가 많다. L1J의 `S_HPMeter`는 대상 ID와 비율을 보내는 별도 구버전 형식이며, 이 체크아웃에서 일반 몹 선택/피격 송신은 확인되지 않았다.

경로 약칭: `T/`=`tools/local_original_session/`, `L/`=`work/local_original_session/`, `R/`=`work/local_server_rea_20261016/`, `P/`=`R/run103_i2_005_hp4ec8_subscriber/notify_consumer_actual257/resume_source_path/hp_consumer_chain/`, `J/`=`D:/SingleLineageRef/l1j-en-classic/src/l1j/server/server/`. `fN`은 protobuf 필드 번호다. 아래 주소/offset은 기존 분석의 RVA/16진수이며 현재 프로세스 포인터가 아니다.

### 4F1A — 몬스터 HP 텍스트는 확인, 일반 게이지는 미확정

## 3. 지정 L1J 참고본과의 대조

`J/serverpackets/S_HPMeter.java:28–44`의 직접 생성자는 `(objId,hpRatio)`를 그대로 쓴다. 캐릭터 생성자는 maxHP>0일 때 `100*currentHP/maxHP` 정수 나눗셈, 그 외100이다. 형식은 **`opcode:u8(104=0x68), objectID:LE32, ratio:u8`**이며 protobuf가 아니다. 0..100 clamp는 없고 writeC에서 `&0xff`만 한다(`J/encryptions/Opcodes.java:212`, `J/serverpackets/ServerBasePacket.java:37–50`).

L1J에서 재사용 가능한 것은 대상 ID와 비율을 분리해 생각하는 설계 참고뿐이다. **0xff 숨김, 0x68 opcode, 0..100 범위를 클래식의 4F1A.f2/4EC8.f3 규칙으로 옮길 근거는 없다.**

## 4. 사용자가 화면으로 확인할 탐색 실험 3개 — 이번에는 실행하지 않음

다음은 요청에 따른 **미확인 가설을 구별할 제안값**이며 정상 서버 payload나 제품 송신 계약이 아니다. 특히 4F1A의 `f2=100,f3=0`과 4EC8의 `f1=UID,f2=표시,f3=비율`은 탐색용 가정이다. 기존 문서가 금지했던 임의 값을 정상값으로 확정하지 않는다. 실제 정상 f2/f3가 확보되면 해당 값을 고정해 대조하는 편이 해석력이 높다.

공통 조건: 기존 정상 로그인→월드 진입→현재 살아 있는 **Monster** 한 마리를 대상으로 한다. `U`는 그 실행에서 실제 등록된 같은 몹 UID이며, 4F1A에서는 **64비트 key와 동일한 uint32 값**일 때만 쓴다. 4EC8 가설은 `0<U<=2147483647`일 때만 가능하다. UID를 임의로 줄이거나 과거 UID2를 재사용하지 않는다. 서버 실제 HP·저장·선택 소유권은 유지하고 표시값만 비교한다. 사용자가 직접 선택/해제 화면을 보며, 시험 담당자는 기존 전송 경로를 사용한다. 새 hook·setter 직접 호출·자동 UI 입력은 실험의 전제에 넣지 않는다.

| 순서 | 보내 볼 값(전체 제안 필드) | 고정/변화와 구별할 결과 |
|---|---|---|
| **A. 4F1A current/max 소비** | `4F1A {1:U,2:100,3:0,4:100,5:100}` → 같은 필드에서 **f4만50→1**. f6/f7은 미송신. | 먼저 선택한 몹, 이어 선택 해제한 같은 몹에서 비교. `100/100(100.00%)→50/100(50.00%)→1/100(1.00%)` 텍스트만 바뀌면 확인된 debug 경로와 일치한다. 막대 길이도 바뀌는지는 별도 기록한다. **텍스트 성공만으로 일반 HP바 성공이라 하지 않는다.** |
| **B. 4F1A f2 비율 가설** | `4F1A {1:U,2:100,3:0,4:50,5:100}` → **f2만50→1**. | f4/f5를50/100에 고정한다. 텍스트는50%인데 막대만100%→50%→1%로 변하면 f2의 게이지 관여를 지지한다. 무반응이면 f2 무효라고 확정하지 않는다(unknown f3·현재 HUD·구독 상태가 남음). |
| **C. 4EC8 UID/표시/비율 가설** | `4EC8 {1:U,2:true,3:100}` → **f3만50→1**; 다시 `{1:U,2:true,3:50}`을 확인한 뒤 **bool만false**로 바꾼다. | 비율에 따른 막대 변화 및 bool 전환의 표시/숨김 여부를 본다. 전부 미확정 의미를 시험하는 가장 약한 안이다. 잘못된 대상/다른 UI 반응도 기록한다. L1J의0xff 숨김은 여기서 시험하지 않는다. |

각 안은 앞 응답/화면 상태를 확인한 뒤 한 값씩 보낸다. 정상 칼 공격/피격 직전·직후에도 같은 대조를 한 번씩 해 **패킷으로 바뀐 표시**, **선택으로 켜진 표시**, **타격 연출만 발생**을 구별한다. 공격4E31 f4를 HP값으로 바꾸거나 가짜 피해/사망을 만들지 않는다. 원래 공격과 HP 통지의 공식 필수 순서는 이번 자료로 확정할 수 없다.

최소 결과는 **같은 현재 U·선택 여부·전송 필드·타격 전후·텍스트/막대 각각의 화면 변화**다. A/B가 무반응이면 f3의 정상값과 현재 HUD 종류가 첫 부족 입력이다. C가 무반응이면 대상/소비자까지 미확정이므로 같은 값을 반복해 전체 경로 부재로 결론내리지 않는다. 새 상시 guard·검증 도구·파일 해시 확인·요청 중 판독 대기는 필요하지 않다.
