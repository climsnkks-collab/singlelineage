## 6. 새 월드 구조에 얹는 권장 설계 초안

이 절은 **향후 설계 권고**다. 이번 감사에서 구현하거나 동결 기능을 발주하지 않았다. 마법·공속·부활 수치가 없는 부분은 unavailable로 두며, 출처를 밝힌 LOCAL 정책과 원본 규칙을 분리한다.

### 6.1 현 구조의 실제 제약

- `T/world_entities.py:22`의 Kind는 PC/NPC/ITEM이며, `:46`의 EntityRef는 UID/generation을 분리한다. 기존 공간 인덱스·move/kill/remove를 공유할 수 있다.
- `T/npc_ai.py:127`은 spawn-group monster로 brain을 만들고 `:207`·`:218`은 PC만 적으로 취급한다. 저장 class3 동료를 NPC 목록에 넣는 것만으로 동료 AI가 생기지 않는다.
- `T/world_visibility.py:259`의 present는 spawner.visible, `:270`의 spawn builder는 spawner.monster_for에 묶여 있다. 동료 provider·종류별 spawn/despawn이 필요하다. `:465`의 이동·관심범위 출판을 공유할 수 있다.
- `T/world_combat.py:273`의 PC 자원과 spawner의 monster HP가 갈라져 있다. `T/world_visibility.py:540`의 pc_attack→HP감소/AI/kill/reward와 `:485`의 npc_attack을 공통 피해 결절로 연결해야 한다.
- `T/world_reward.py:119`는 solo PC에 전체 경험치와 드롭을 계산한다. 두 번 호출해 동료 몫을 만들면 경험치/드롭/RNG가 중복된다.
- 실제 성장 저장은 `T/broker.py:1574`, `:4236`의 `ProgressStore.commit` 경로다. `T/world_persist.py:74`는 큐/flush 모듈이나 비시험 .py에서 정의 외 소비자를 이번 검색에서 찾지 못했다. 이미 제품 저장에 통합됐다고 가정하지 않는다.
- `T/world_pet.py:49`는 NpcAi가 pets를 제어하지 않는다고 명시한다. pet 명령/성장/목걸이 순수 API와 character-companion 영속 어댑터는 구별한다.

### 6.2 제안 모델·행동 우선순위

**추론/권고:** 동료는 새 창이나 별도 Runtime이 아니라 **월드 엔티티 + CompanionBrain + 기존 자원/저장 어댑터**로 둔다.

- 영속 신원: account/member(저장 플레이어 동료) 또는 pet ID. 주인 신원·장비/학습/성장/HP·MP·명령/지원 설정·반단위 carry를 연결한다.
- 일시 신원: owner_ref·actor_ref·target_ref는 EntityRef로, 새 접속/소환마다 재발급한다. 과거 actor UID/lease/타깃을 저장에서 부활시키지 않는다.
- 상태: STORED → FOLLOW/WAIT → CHASE → ATTACK/CAST → FOLLOW, 그리고 RETURN/DEAD/RETIRING. 명령(ASSIST/DEFEND/PASSIVE·FOLLOW/STATION)과 행동 상태를 별도 필드로 둔다.
- 우선순위 초안: 수명/사망·주인 이탈 처리 → 현재 시전의 완료/UNKNOWN 보존 → 허용된 긴급 힐 → 필요한 지원 → 주인/자기 사건으로 정당하게 얻은 적 공격 → 거리/LOS 자리 잡기 → 추종/대기. 세부 HP·거리·주기는 확인된 데이터/명시 LOCAL 정책으로 받는다.
- WorldRuntime의 같은 lock·Scheduler를 사용한다(`T/world_runtime.py:69`, `:80`; `T/world_scheduler.py:49`). 구 Host poll loop·중복 타이머·별도 피해/EXP 엔진을 새로 살리지 않는다.
- 클라 표시는 `4E96`(등록), `4E2C`(이동), 기존 확인된 공격/사망/`4E40` 빌더를 종류별 어댑터로 재사용하되 **원문확인/packet 관측/native 화면** 상태를 분리한다. Player4E2C f2의 옛 LOCAL pre-step 관례를 원본 의미로 확정하지 않는다.
- 원본 명령창은 `4F13/4F14/4F02` 근거로 연결할 후보지만 Player 외형 등록을 Pet/Summon으로 바꿔도 된다는 결론은 없다. `4E96.f67=1/2`는 비Player·appearance subtype·소유 이름 조건이 있는 별도 경로다(`R/run396_pet_control/spawn_hp/findings.md:13`, `:17`). 동료 외형·종류·원본 클릭의 호환성을 먼저 확인한다.
