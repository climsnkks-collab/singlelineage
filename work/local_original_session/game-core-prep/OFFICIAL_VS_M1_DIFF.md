# 공식 사전과 M1 차이

작성 기준 UTC: 2026-10-26T17:29:35.877078+00:00. 네트워크 호출·게임 실행 없이 보존한 이번 수집 원문과 M1 스냅샷에서 재계산했다. 값 적용·코드 변경은 하지 않았다.

## 비교 기준과 범위

M1 items.json 전체 40행, monsters.json 전체 4행, drops.json 전체 4개 몬스터 목록이 대상이다. enchant.json 장비 30행의 안전 인챈트도 보조 대조했다. 상세 비교 행 전체와 원출처는 `work/official_data/normalization/comparison.json`에 있다.

**원문 수집은 완결됐지만 요청 간격 요건은 실패했다.** 재시작 때 구 Python 자식이 약 15초 남아 새 수집기와 겹쳤다. 실제 GET 1125회 / unique URL 1111개 / 중복 14회, 네트워크 실패 0·인증 skip 0이다. 최소 시작 간격 0.055700063705초, 사용자 1.0초 미만 26쌍(수집기 설정 1.05초 미만 27쌍). 사용자 간격 위반 구간은 UTC 2026-10-26 17:04:59.121~17:05:12.775다. `manifest.json`의 `summary.network_exception`/`summary.verification`과 `collection_attempts.jsonl`에 원로그·개별 위반·실제 원문 시각 계보를 보존했다. 간격요건 준수=false이며 이력을 지우는 재수집은 하지 않았다. 원문 1111파일의 hash/JSON/ID·실제 수집 시각 계보 확인은 정상으로 기록됐다.

몬스터 클라이언트 대응 합계는 343개(정확 333 + 공백만 차이 10), ID 부재 23개다.

고정 클라이언트: `work/source_game_data/native-dump-v1.jsonl`(각 행 ID·KR 이름·원행 body SHA), `provenance.json`의 버전 26.09.29.2001. 같은 이름의 다른 ID는 연결하지 않았다. 같은 ID에서 양끝 공백만 다른 이름은 별도 status와 양쪽 원문·str.strip 규칙으로 표시했다. 그 외 ID 부재·이름 불일치 행은 client_id=null이며 공식 새 항목/업데이트로 단정하지 않는다.

## 비교 의미

- 무게는 M1 raw/1000과 공식 정수 표시를 비교했다. floor(M1 raw/1000)가 공식값이면 표시정밀도 차이로 분류했다. 공식 정수값만으로 내부 정밀 무게를 역산할 수 없다. 화살은 M1 raw30, client f10=47로 다르지만 둘 다 공식 표시0과 양립하므로 공식 충돌로 세지 않았다. client raw 차이는 comparison.json에 별도로 보존했다.
- 방어구 AC는 M1 음수 기여의 부호를 반전해 공식 양수 크기와 비교했다. 피해는 enchantLevel=0 응답의 origin이며 extra와 합치지 않았다.
- classNames 부재/빈 배열의 전 직업 비교는 기존 공식 UI `itemdict.js`의 classNames?.length>0 ? join : common.all 관례에 따른 해석이다. 정규화 원문은 부재와 전 직업 문자열을 혼동하지 않게 null+사유를 유지한다.
- oneHanded는 의미 미확정인 원문으로만 보존했다. 양손은 options의 “양손” 문구가 있을 때만 true다. 미제공 옵션·키를 0/false로 채우지 않았다.
- 안전 인챈트는 “+N까지 안전”의 N을 추출한다. “+1부터 실패할 가능성 있음”은 안전 단계 0으로 명시 해석했다. “인챈트 불가”는 safe_enchant=null/enchantable=false로 구별하며 원문 부재는 가능 여부 미확인이다.
- 드롭은 순서를 무시하고 (ID, 저주/축복 접두어 포함 이름)으로 비교한다. 확률·수량·아데나 양은 공식에 없으므로 구성 일치를 확률 일치로 확대하지 않는다.

## 누락 계약과 적용 경계

몬스터 4종은 이름·레벨만 직접 수치 대조 가능하다. HP·MP·AC·경험치·공격 피해/STR·선공·이동/공격 간격·행동 범위·시체 정리 시간은 공식 상세에 없어 기존 client/L1J/local_policy와의 충돌을 판정하지 않았다. 크기·손상·언데드·출현지역은 공식 원문에 있는 경우 보존하되 M1 대응 필드 부재를 구별했다.

아이템은 피해·AC·무게·직업·안전 인챈트·회복범위를 비교했다. 원문 옵션(명중·추가 피해·지속시간 등), 재질, 세트 구성/보너스, 거래/보관/버리기/삭제, 착용 레벨, 획득처·사용처 등은 official 및 fields에 누락 없이 보존한다. M1에는 세트/재질/손상 등 원문과 같은 구조가 없어 별도의 소비 계약이 필요하다. M1 icon·token·slot·stackable·weapon_type 등은 공식과 같은 의미로 증명된 필드가 아니거나 분류 체계가 달라 수치 일치로 주장하지 않는다.

마법 110개는 정규화만 수행했다. alginName 철자, 단계, 원문 효과·지속시간·대상/사거리·classNames·learnings·consumables·textbook을 보존했다. 이번 M1 지정 비교 대상에는 spells.json이 없다. HP/MP 소모 키의 부재는 0이 아니며 습득 레벨 문자열을 추정 수치로 바꾸지 않았다.

이 결과는 데이터 원문·정적 비교다. 서버 소비, 아이템 회복 분포, 클라이언트 화면·입력·동작 동등성을 검증한 PASS가 아니다. 적용은 별도 다음 단계다.
