Start uses a try-only lifecycle lock, permanently pins the containing module with actual entry-point address before creating an event or thread, creates a manual-reset cancellation event and one CreateThread worker. One attempt per process; no reconnect/restart. The worker performs a cancellable, bounded 10,000ms event wait. This is a genuine worker lifetime, **not yet a bootstrap file reader, named-pipe client, parser or selected UI**. Future overlapped IO must use the same event plus an absolute remaining deadline, cancel its actual issued IO, drain completion and preserve this module/state lifetime; no current code claims those future IO operations are implemented.

Off-thread host Revoke signals the worker event without User32, sender access, lock acquisition or joining. Cancellation racing event publication is latched and signalled after publication. The cancellation event stays process-lifetime so concurrent Revoke never races a closed/recycled event handle. Permanent module pin is deliberate even after a successful worker join; no unload claim. At most one event is retained, also on thread creation failure. It is reclaimed by process teardown.

Terminal owner shutdown invokes lifecycle Stop(0), revokes and checks thread completion without blocking the UI. Existing sender Stop on a world/context transition remains sender-only; it must not prematurely cancel the independent bootstrap transport while a login/world transition is pending. Native Finish invokes Revoke(true) and FinishIo: Join(0) on the owner thread, otherwise a bounded 2000ms join. Join also clamps erroneous budgets to 2000ms and uses a try-only lock. WAIT_OBJECT_0 closes only the completed thread handle. Timeout/WAIT_FAILED/concurrent Start-or-Join returns UnknownRetained and preserves thread handle, event, state and pinned code. `host.LastJoin()` and `host.Completed()` retain the exact observations. UNKNOWN does not become clean close or unload success; no TerminateThread, synthetic completion or callback lifetime erasure. A subsequent existing terminal callback/Finish may reap a genuinely completed thread without starting a new one.
