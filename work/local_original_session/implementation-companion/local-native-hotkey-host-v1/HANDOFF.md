## Genuine caller and source changes

Its `InstallAutoOkHook`, called by the successful original connect result, records `manual_move::uiThread`, binds the existing diagnostic owner, stores the selected HWND and installs `AutoOkGetMessage`. `AutoOkGetMessage` calls `BeforeUi` before the original handlers and `AfterUi` before all sixteen existing Forward return sites. Messages remain intact; all original handler order/dispatch/CallNext behavior remains. The inverse check removes just these additions and compares byte-for-text against the exact parent. `OwnLoginCloseBridge`, `OwnLoginSelectedBridge` and the actual `OwnLoginFinishAfterCallbacksJoined` entry now revoke before their original bodies; all original ABI/forwarding bodies remain unchanged.

On the existing owner UI thread, `AfterUi` observes the actual WORLD5/root/registry/scene/selected UID using the v2 retained snapshot. This observation does not require foreground and can detect world retirement in the owned background desktop. Installation separately requires v2's exact foreground `ObserveExpected`, then one persistent `Sender` and `Binding` call into `local_companion_key::Install`. The existing hotkey accepts physical Ctrl+Shift+M first keydown only; it never gives focus, moves the cursor, injects input or consumes the message. One press invokes at most one original sender attempt; there is no send retry or success claim.

Same observed selection does not repeatedly install. Focus loss leaves dispatch ineligible without manufacturing a selection change. Source-observed world exit closes/retire/releases the binding; a different observed world can be captured and armed. A failed installation is remembered for that exact selection, with no automatic retry. Native Close/Selected invalidates immediately under a short publication lock, which never covers original sender execution; the UI callback drains/unhooks before destroying its sender storage. Reentrant Close/unhook failure preserves storage and blocks rearm until Closed plus Sender::Retire. A close/reselection whose intermediate non-WORLD transition is never observed and whose pointer/UID identities are reused remains conservatively blocked; no native epoch or ABA-resistant lease is invented.

## Teardown and remaining boundary

WM_QUIT or queued window destroy indications, existing terminal/owner loss and source quit results revoke and close on the owner thread. Native Finish-after-joined makes revocation final. If Close/Selected/Finish runs on a background thread, it only revokes there; unhook/drain is done at the next real owner UI callback. If no further owner callback exists, the binding stays revoked and pinned until Windows process teardown removes the hook. No owner-thread message is synthesized and no unload/drain completion is fabricated. Host Sender storage intentionally has process lifetime with no CRT destructor, so this pending state cannot destroy an active callback context. Existing hook code pins its module; original image/queue lifetime still follows the parent native host, not a new guarantee.

Thus a genuine current-world invocation and owner-thread close/rearm source now exist. Production DLL build/source selection, immutable launcher/product pins, actual selected WORLD invocation, physical hotkey, UI-thread unhook/failed-unhook behavior, native F101 wire, server current/session acceptance, actor rendering, reconnect and original queued clone drain remain UNRUN/UNKNOWN. In particular, Finish on a nonowner thread with no later UI callback is revoked/pending rather than claimed Closed. No changed product pin was published or Test UI gate introduced. If the requested contract requires deterministic owner-thread Close before teardown even without another natural callback, that is the first remaining lifecycle caller requirement; this source deliberately does not invent it.
