## Required supplied API

The shared owner must supply an opaque exact-type capability with issuer registry/caller admission, not a user-constructible DTO or a boolean ambient bypass. Required operations are synchronous capture, pending-current validation with a live HP snapshot, and idempotent revocation. Only the exact sealed Allied RootPlayers consumer and original selected Broker._send may issue/consume it; ordinary BrokerProvider.current, BatchStore._current, status.current and ResourceOwner.validate_projection retain their existing pending refusal.

**Capture** occurs after the last awaited prewrite checkpoint and all existing synchronous prewrite checks, immediately before policy.begin_write. At this point policy pending_opcode is None, pending_size is zero, drain_started_ns is None, and sent equals the Allied RESERVED sent count. Capture must execute the ordinary full current path first, under the existing Store/character/realm lock order, and validate a fresh complete BatchStore read. It must bind:

- issuer RootPlayers/PlayerRegistration identity, registration generation and phase, actual registered frame object and bytes, opcode/size, direct writer and row, exact policy row and sent count;
- original running task, owned canonical scope, exact operation lock, selected Binding/generation, Host/selected state, player lifetime, direct CharacterLease and companion CharacterLease (including owner/profile/UID and current lease registry);
- exact BatchStore, source inventory Store, provider, canonical account/path, owner registry, current raw canonical bytes/digest and in-memory document, plus both direct and companion RESOURCE participant UID/revision/digest/document;
- current HP status snapshot and its original lifetime/projection, pose/map/grid/alive state required by Allied.operation, with the companion RESOURCE digest still equal to PlayerRegistration.resource_digest from DTO preparation.

The post-checkpoint full current must match the registered operation; an actual change is refusal. The captured data does not become authority by itself. A borrowed read must freshly validate Store currentness and participant revisions each time. Store read authority is the missing shared primitive: provider.delivery_current checks selected structure only, and calling existing Store._current still invokes ordinary provider.current and refuses pending. Do not use either as a complete substitute.

**Pending validation** must admit only this capability, same frame/writer/row/task/scope/selection/leases/Store, and the exact pending policy tuple (opcode, size, drain_started_ns, sent). Bind drain_started_ns once after original begin_write, before WRITE_ATTEMPTED/writer.write. On every consumption compare a fresh complete Store read to the captured raw/document and RESOURCE versions, and validate a newly obtained HP snapshot through the supplied ResourceOwner projection API. Keep original HP status lifetime, selection, pose, life and source checks. Support required SKILL/shield projection consistency when the selected ResourceOwner currently requires it; a RESOURCE-only copy must not skip that existing branch. Any changed Store, participant, issuer/source, task, binding, lease, policy or lifetime invalidates the capability. No ordinary current call acquires pending authority merely because a capability exists.

**Revocation** is synchronous and idempotent; it must succeed even when current validation already fails. Revoke at original per-wire _send finally (success, error and cancellation), and at RootPlayers.close/Host selection retirement or connection cleanup before authority is discarded. Cleanup of transport authority does not release an UNKNOWN companion lease, erase a registration, reset a UID cursor, clear pending, or claim client absence. Reusing a revoked capability, a different equal-by-value frame, another task or later removal send fails. Retain the original first exception; revocation cannot mask it.
