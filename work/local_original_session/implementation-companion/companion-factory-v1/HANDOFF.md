The unchanged v5/current contracts expose three concrete remaining joins:

- `_attach_companion` requires the canonical account `broker.realm.store.path`
  to equal this Plan's `self.profile`. Current CreatedCharacterScopes uses the
  account realm but child inventory profiles under `character-state/<uid>/`.
  A child Plan therefore cannot use this unchanged identity check. Do not simply
  relax it; an explicit account/character owner contract is needed.
- Current child preparation is RESOURCE-only unless the existing scoped SHOP
  source builds a full graph. Reviewed `bind_companion` rejects RESOURCE-only;
  shared support requires actual joint SKILL. Current rebuild methods do not
  carry companion configuration. Host attach separately requires an unstarted
  broker and empty sessions, while a real scope transition reuses its live
  broker. These are independent source constraints; passing cold imports does
  not establish a safe Host rebind across created scopes.

  closes shared/source references. Original Broker hooks own asynchronous actor
  retirement. This Factory never force-clears a selected state or lease, and
  the reviewed Host does not clear broker/realm Host references in `closed()`.
  Scope/reselection support needs one reviewed owner transition; it must not
  duplicate Host/shared authority or bypass the retained lifetime checks.

The completed canonical Batch/RESOURCE, ACK/realm and Broker descendants are
needed in the eventual exact graph; the real schema/lifecycle joint graph and
