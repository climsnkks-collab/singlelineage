## First missing producer and narrow proposed contract

**Missing producer:** a launcher-owned `LocalUiChannel` issuer created for the actual retained NativeOwner before resume, whose selected binding is installed by the real Host under its existing Broker row operation. Neither source contact exists in the inspected selection. Implementing a free-standing named pipe now would provide neither genuine selected admission nor deterministic native close.

The following is a proposed contract, not supplied access or a new callable API claim:

- **Bootstrap ownership:** create one local-only pipe instance for the actual owner process lifetime, first-instance ownership, bounded framing, explicit user/logon ACL, remote rejection and no permissive fallback. Deliver its unpredictable endpoint and one-time capability through a separate versioned bootstrap artifact or explicit inherited handle, without modifying the strict diagnostic context. A future separate artifact needs its own creation/access/lifetime policy and native reader. The endpoint must not be chosen by a game-supplied UID.
- **Mutual process admission:** server verifies connected pipe client against the existing retained process handle/PID/birth/Job; native verifies pipe server against the launch controller identity supplied by the trusted new bootstrap and completes the one-time capability handshake. The current context does not supply that server identity or secret. Same-user ACL alone is not a selected-session binding. Reject reuse, duplicates, reconnect replay and mismatched instance; do not accept claimed process ids from JSON.
- **Selected binding producer:** inside the existing Host row operation, bind the channel to the exact broker/writer/row, selection, direct lease, current companion lease/actor generation and UI epoch. Existing NativeOwner-to-row ownership must still pass. Keep these object identities on the server. Send an opaque, revocable binding id plus panel generation/revision. A native WORLD snapshot/selected UID is a consistency observation, not the authority that creates this server binding. A new Host/adapter registration edge is needed because current `interface.open` lacks it.
- **Model and commands:** OPEN/RENDER/CLOSE carry bounded typed snapshots with binding, panel generation and revision. COMMAND returns displayed revision, monotonic sequence, enumerated action and bounded values. Receive onto the server event loop and invoke only the retained Host callback; original `Host.command` reacquires the actual row and checks state/epoch. No direct controller call, object-id serialization, original game opcode reuse, or automatic retry of ambiguous summon/dismiss. Refresh replaces the retained callback. Inventory/equipment remain unavailable until real ITEM ownership admission is supplied.
- **Owner thread and lifetime:** pipe IO worker only validates/enqueues immutable data; owner thread alone creates/renders/destroys controls via a reviewed dispatch point. Existing natural BeforeUi/AfterUi are possible poll contacts but no prompt wake/close acknowledgement is supplied. Off-thread Revoke invalidates admission immediately. Close acknowledgement requires actual owner destroy and in-flight command/callback drain, not queued CLOSE or EOF. Preserve UNKNOWN/pinned lifetime until teardown if owner dispatch stops; no DLL unload/reuse claim.
- **Host close reconciliation:** current synchronous `interface.close` clears `state.panel` on ordinary return. A future pending transport proxy must not equate enqueued close with native destruction. Supply actual close/drain result or explicitly retain pending/UNKNOWN with the Host lifecycle updated in one coherent private descendant. Similarly `open` must distinguish proxy acceptance from actual native OPEN acknowledgement/visible UI. A transport alone proves neither.
