# 규칙 변경 기록

새 사용자 지시는 해당 주제의 현재 규칙 문장을 직접 수정하고, 이 파일에 날짜와 원문 한 줄을 남긴다. 과거 기록은 당시 근거이며 현재 상태나 재개 승인을 대신하지 않는다.

- 날짜별 지시를 주제별 최신 결론으로 통합했다. 현재 담당·실행 번호·중지 상태는 기존 ACTIVE_TASK 맨 앞에서 관리하며, 이번 문서 정리로 제품 작업을 재개하지 않는다.
- 의미 변경은 사용자가 지정한 재사용과 파일 관리 규칙에 한정한다. 코드 조각의 계보 간 재사용을 허용하고 PASS 귀속은 그대로 유지한다. 새 작성 전 기존 구현 탐색, `reused_from` 기록, 새 계보 시험, 대체 큐 항목의 `superseded` 마감을 적용한다.
- 도구는 같은 폴더에서 수정하고 manifest와 해시로 버전을 구분한다. 부모 전체 복사 대신 경로·해시와 변경 파일을 보관한다. 시험 출력은 지정 runs 경로에 모으고 최신 3회와 PASS·첫 실패 증거를 남긴다. 나머지 스크린샷·덤프는 삭제하지 않고 아카이브로 옮긴다. 상위 경로를 가리키는 junction을 만들지 않는다.
- 문서 크기 상한과 주제 직접 수정 방식을 적용하고, 사용자가 제공한 외부 아카이브·junction 위치를 AGENTS에 안내했다. 이번 작업에서는 실제 파일 이동·정리·junction 변경을 하지 않는다.

### 큐 도구의 후속 변경 제안

`tools/integration_queue.py`는 수정하지 않았다. 90–92줄의 허용 상태는 `queued`, `in_progress`, `blocked`뿐이며, 181–185줄의 `complete`는 `in_progress` 항목만 닫는다. 현재 도구로는 새 ID 등록과 옛 항목의 `superseded` 마감을 한 작업으로 보장할 수 없다.

후속 변경은 기존 잠금·원자적 저장 안에서 새 ID 등록과 옛 ID 대체 마감을 함께 수행하는 기능을 추가하는 것이다. 옛 ID·새 ID·대체 이유를 기존 근거에 남기고, 대체된 항목은 실행 가능한 큐나 `blocked`에 남기지 않는다. 상태 검증과 CLI, 해당 원자성·중복·실패 보존 검사를 함께 갱신할 필요가 있다. 별도 큐·로그 체계는 만들지 않는다.
