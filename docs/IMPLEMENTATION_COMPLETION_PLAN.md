원본 동작의 consumer·raw frame·필드 의미가 확정된 값은 그대로 사용한다. 서버 참고 룰은 기존 조사에서 고정한 L1J-EN/classic commit `103e6f6c9dd83545959d8e87d3f59f8de1f40ef0`부터 검토하며 원문 파일·commit·hash·라이선스 고지를 보존한다. 이 저장소의 대상은2009 US 클라이언트이고 현행 NC 서버의 같은 수치를 보장하지 않는다. 참고 ID와 현재 client ID를 직접 합치지 않는다. 비지원 특수 분기는 명시하고 후속 구현 대상으로 남긴다.

진행 순서:

1. 실제 코드 inventory와 우선순위를 고정하고, common getter·싱글 전투/성장 core·상태/렌더링 통합을 병렬 진행한다.
2. 일반 actor ingress와 싱글 authority의 상태/action/event 계약을 연결한다. 게임 루프에서 상태를 생성해 기존 typed client 표시 경로에 공급한다.
3. 인벤·장착·드롭·경제와 스킬/버프/죽음·보상을 채우고 durable save와 시작 흐름을 연결한다.
4. 데이터/지도/캐릭터 지원 범위를 확장하고 남은 비지원 기능을 완료 inventory에서 닫는다. 실제로 코드에 없는 기능을 완료로 바꾸지 않는다.
5. 기능별 정적 코드 검토·원문 재독 뒤 실제 native/unit/headless/pixel/GUI·플레이 검증을 진행한다. 변경 범위에 맞는 검사를 완료하고, cold boot·사냥→보상→저장→재기동 전체 흐름을 통합 제품에서 확인한다. GUI/OS 입력은 병행 채팅과 조율한다.

구현 완료 보고에는 실제 연결된 기능과 데이터 지원 범위, 미확인 원본 동등성, 공개 참고 룰의 출처 및 아직 실행하지 않은 검사를 구분한다. 실행 검사가 유예됐다는 이유로 구현을 중단하거나, 구현/컴파일 결과만으로 게임 플레이가 검증됐다고 표시하지 않는다.
