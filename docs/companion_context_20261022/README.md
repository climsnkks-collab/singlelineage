# 동료 법사 구현용 최신 자체 소스 문맥 · 2026-10-22

이 묶음은 공개 main `f599fd7af903e0724999fff110601c8a724d52f0` 밖에서 진행한 최신 자체 구현의 읽기용 사본이다. 실제 원본 코드 36개를 그대로 복사했고 [SOURCES.md](SOURCES.md)에 각 원경로와 SHA-256을 기록했다. 이 폴더 자체는 실행 가능한 선정 cohort나 게임 실행본이 아니다. 원본 바이너리, 사용자 저장, 실행 로그, REA 원문, 런타임 JSON, 인증정보는 포함하지 않는다. `main`이나 기존 작업 브랜치의 파일을 바꾸지 않는다.

## 사용자 확정 요구

- 실제 생성한 플레이어블 법사를 같은 캐릭터로 동료 소환한다. 직접 플레이와 소환 역할이 동시에 활성화되지 않아야 한다. 장비·인벤토리·성장·학습·HP/MP의 정본은 공유한다.
- 동행 지원과 지정 지역/제자리 지원, 힐·버프·물약 설정을 제공한다. 실제 사거리·자원·학습·쿨다운·아이템 소유를 공용 제품 경로에서 소비한다.
- 처치 경험치는 함께 받는 경우 본캐와 법사 50:50이다. 한 처치의 기존 전체 지급과 중복 정산하지 않는다.
- ATS는 화면 배치·버튼·조작 방식만 재사용한다. 동료 설정과 실행은 기존 자동사냥과 분리한다. 기존 인벤토리·장비 UI를 대상 법사에 연결한다.
- 최초 진입은 충돌을 확인한 단축키로 연결하고 새 메인 아이콘은 후속으로 남긴다.
- 웹 Pro가 동료 구현과 수정본을 소유한다. 로컬 통합은 실제 변경분 검토와 연결, 전담 Test는 기존 비입력 백그라운드 시험을 맡는다. 구현 완료를 기다리며 다른 제품 작업을 중단하지 않는다.

## 읽을 순서와 실제 상태

1. `npc387/npc_continuous_retaliation_runtime.py`, `npc_continuous_retaliation.py`, `npc_session.py`, `npc_edge.py`, `manual_move_commands.py`, `broker.py`는 실선정387의 원파일이다. 이동한 플레이어를 따라온 같은 적 NPC의 server/client 격자 일치와 그 뒤 새 반격·HP 감소까지 실제 시험했다. 특정 적 NPC의 현재 UID/gen/Controller/owned goal을 보존하는 코드이며 아군 법사 구현이 이미 존재한다는 뜻은 아니다. `shared/npc.py`는 기존 원 SC4E96 spawn 준비/월드 전송의 실제 호출부다. 새 동료는 기존 적 NPC를 재명명하거나 UID를 상수로 겹치지 않게 하고 캐릭터 UID와 실제 actor UID의 수명/소유를 연결해야 한다.
2. `combat386/`는 전투 전담이 작성·인계한 공유 스탯/물리/마법과 기존 RESOURCE/SKILL 비용·회복·전달 후손이다. 실제 로컬 full-SKILL/Light379 부모와의 통합386-v2는 진행 중이며 이 폴더의 broker 대체본을 NPC387 위에 통째로 덮지 않는다. `combat_magic.py::resolve_heal`, `MagicActor.from_derived`, `combat_magic_cast.py`와 owner/cost delivery의 동일 typed admission→비용/회복 commit→응답 drain을 재사용한다. 이 소스를 실제 동료의 시전·응답 성공으로 표시하지 않는다. 별도 동료 HP writer·비용/쿨다운 ledger나 가짜 self admission을 만들지 않는다.
3. `skill382/`는 기존 Light/Shield에 여러 self 버프를 더한 인계 source다. 정상 학습/현재 자원 입력과 old2→new5 rule의 실제 cold 교체는 아직 통합 중이다. speed/regen의 주문별 정책값은 미확정이며 신규 주문/책/학습/HPMP를 임의로 지급하지 않는다. 실제 성공은 이전 Light의 비용·서버 응답·현재 Actor 값까지이며 타인 법사의 주문 경로는 열린 계약이다.
4. `npc387/equipment_store.py`, `inventory_store.py`, `inventory_aggregate.py`, `item_use_session.py`는 실제 캐릭터 UID별 장비/아이템 정본·CAS·소유·응답 수명 접점이다. 법사용 별도 중복 아이템 저장소를 만들지 않는다. 공개 `tools/local_character_creation/realm.py::CharacterStore`의 캐릭터 조회/생성/저장과 `tools/local_original_session/settings.py`도 함께 읽는다.

현재 공개본과 이 문맥에서 공용 경험치/성장 저장·법사 동시 actor/ATS 화면을 완결 제품으로 구현했다는 근거는 없다. 없는 경로의 존재를 전제하지 말고, 이 기능에 필요한 공유 캐릭터 정본 확장과 실제 소비 연결을 신규 구현 범위로 구별한다. 플레이어블 법사와 동료가 같은 정본을 소비하도록 연결해야 하며, 독립된 가짜 성장 저장소나 소비자 없는 설정 파일을 완료물로 삼지 않는다. 원본 ATS/아군 시전의 미확인 native 계약이 꼭 필요하면 정확한 함수/필드·실패 지점만 로컬 통합에 요청하고 독립적으로 진행할 수 있는 구현은 계속한다.
