# 싱글리니지 작업 규칙

사용자 지시·권한이 우선한다. 담당·소스·결과·중지 상태는 [현재 상태](ACTIVE_TASK.md)와 기존 인계에 둔다. 문서·소스 도착으로 권한·재개·완료를 만들거나 재승인을 추가하지 않는다. 후속에도 승계한다.

## 1. 현재 목표와 시험 방식

- 제품 목표·원본 보존·폐기 경계·독립 실행은 [상위 지침](../AGENTS.md)을 따른다.
- ACTIVE_TASK 7장의 현재 마일스톤(지금은 게임 뼈대 → M1 사냥터 30분)이 끝날 때까지 새 기능을 시작하지 않는다. 마일스톤 완료는 원본 클라이언트로 30분 직접 플레이해 판정한다. 파이썬 서버를 유지하고 L1J는 데이터·설계 참고로만 쓴다.
- 동료·창고·공격마법·버프 확대·상점 확장은 동결하고 기존 결과와 큐는 보존한다. 리셋 전 남은 사용량은 현재 마일스톤 안의 서로 독립된 영역에 병렬로 쓴다.
- 1일차는 현재 소스 조합·정상 시작 저장·무기·NPC 선정, 기준 실행과 첫 실패 주변에 집중해 이동·선택·칼 공격·NPC HP 감소를 연결한다. 2일차는 반복 공격·반격과 PC HP·사망 및 공격/반격 종료·경험치와 실제 보상, 3일차는 저장/로드·재접속·죽은 NPC 정리·다른 NPC·다음 사냥을 연결한다. 앞 단계가 되면 다음 날 단계를 당긴다. 상세 계획은 [ACTIVE_TASK 7장](ACTIVE_TASK.md)을 따른다.
- 입력이 없으면 버전을 늘리지 않고 첫 실패·부족한 입력·최소 관측을 남긴다. 원본에서 확인하지 못한 서버 계산식·속도·opcode·native 계약을 추측해 원본 규칙으로 확정하지 않는다.
- worker는 막힘 하나의 원인 확인·연결 수정·실제 동작 1회 실행을 한 단위로 끝낸다. 작은 오류는 같은 worker 안에서 해결한다. 값 생산자·소비자와 실제 소비·저장·수명·정리를 연결하고 무관한 전체 호출 그래프·프로토콜 복원을 선행하지 않는다.

### 정식 PASS와 개발 시험

- 정식 PASS는 정확한 소스 해시 조합·시작 저장에 귀속한다. 로컬 시험 서버·시험 저장 사본에서 정상 로그인 → 캐릭터 선택 → 월드 진입과 실제 플레이 순서의 직접 패킷으로 실제 디코더·라우터·핸들러를 통과한다. 앞 응답·상태를 확인한 뒤 다음 요청을 보내고 서버 발급 세션·목록 reference·UID·current·소유권을 쓴다.
- 정상 경로로 만든 시작 저장, 예를 들어 무기를 들고 월드에 들어온 직후의 저장에서 해당 행동만 시험할 수 있다. 시작 저장과 통과 범위를 적고 로그인·월드 진입을 포함한 전체 성공으로 확대하지 않는다.
- 개발 중 함수 직접 호출·시험 데이터는 허용하지만 정식 PASS가 아니다. 정식 PASS에서 가짜 패킷·핸들러 직접 호출·상태 강제·최종 행동 선발송·UID/영수증 위조·가짜 성공·소유권/거래/저장/current/CAS/수명 guard 삭제로 통과시키지 않는다.
- 실제 선택 → 메뉴 → 항목·수량 → 확정의 순서와 패킷 없는 클릭의 다음 요청값 반영을 필요한 행동에서 확인한다. Windows 메시지·입력 자동화·클릭 DLL·사용자 클릭 대기를 직접 패킷 시험의 선행조건으로 삼지 않는다.
- 서버 계산에 미사용인 client-local 표시·입력 메타데이터만 필수 형식·출처를 밝힌 LOCAL peer 값으로 줄 수 있다. 실제 행동 순서·소비 입력은 확인하고 세션·참조·UID·current·소유권·거래·저장·CAS를 대체하지 않는다. 해당 4E28 추가 i32는 0/0이다. 미사용 필드의 원화면 geometry·Camera 복원을 선행하지 않는다.
- 전송 반환·요청 수신·응답·상태·필요 저장/복원을 구분한다. 마지막 성공·첫 실패·미확인·원오류를 실제대로 남긴다. 패킷 PASS를 Native 클릭·렌더링·입력·충돌 해결로 확대하지 않는다.
- 같은 소스도 재현·환경 분리·성능 목적의 재시험을 허용하며 결과를 모두 보존한다. 다른 소스·저장·실행 계보의 PASS를 합산하지 않는다. 실패한 경로만 멈추고 독립 작업은 계속한다.

### 원본·저장과 실행 보존

- 원본 LC·바이너리·자원·사용자 저장·보관/·PASS 사본·원소스·실패 원문을 보존한다. 특정 초기화 허용은 일반 원본·저장 수정 허용이 아니다. current·UID·UIDburn·소진 기록·상품·items·cash·history·MP·부분 저장·복원을 해당 계약대로 보존한다.
- 실제 게임·포트 시험은 일회성 시험 worker 하나가 한 번에 하나만 실행한다. 검증된 owned non-input desktop/Job의 백그라운드 경로를 쓰고 사용자 포커스·커서·전역 입력에 간섭하지 않는다. 일반 권한·창 없는 작업을 우선하고 필수 도우미를 재사용하며 실패·취소 UAC를 반복하지 않는다.
- 이전 PID·포인터·receipt·객체 상태를 현재 실행의 근거로 쓰지 않는다. 실제 환경 조건을 mock·정적 검사로 대체해 정식 PASS로 표시하지 않는다.
- 살아 있는 게임은 기존 Quit로 종료 요청하고 원 finally/FIRST close·부분 보존·소유 자원을 정리한다. 정상 종료·강제 종료·UNKNOWN을 실제 결과대로 남긴다.

### 확정된 사용자 정책

아래 기능별 정책은 기존 결과와 함께 보존한다. 동결된 기능의 재개 권한이나 현재 마일스톤의 선행조건으로 삼지 않는다.

## 2. 재사용과 상태 판정

- 새 작성 전에 같은 기능의 기존 구현을 찾아 재사용한다. 못 쓰면 이유를 짧게 남긴다. 이름으로 후보를 찾을 수 있으며, 이름만으로 동일 소스·PASS를 주장하지 않는다.
- 다른 계보의 코드도 재사용할 수 있다. 기존 manifest의 `reused_from`에 원파일·해시·원큐 ID를 남기고 새 조합의 실행으로 판정한다. 전체 부모 체인 증명을 선행하지 않으며 원래 PASS가 이전되지는 않는다.
- 같은 조건·범위의 성공은 재사용한다. 변경·직접 영향·새 실패에 집중하고 세션 교체·문맥 복구를 이유로 전수검사하지 않는다. 재현·환경 분리·성능 목적의 재시험은 허용한다.
- SOURCE는 자료 준비, OPEN은 잔여 계약·결함·관측, UNKNOWN은 근거 부족·관측 불가·도구 미해결이다. PASS는 입증한 조건·단계뿐이다. 컴파일·원문·callback 반환·요청 수신·저장·화면 반영은 서로 대체하지 않는다.
- 정적·메모리 사실과 실행 관측을 구분한다. 도구 실패를 제품 버그로 단정하거나 UNKNOWN을 PASS로 바꾸지 않는다. 버전 수·PASS 비율·worker 수를 성과로 세지 않는다. 성과는 막힘 하나를 닫는 데 쓴 토큰과 현재 마일스톤의 실제 연결 단계다.

## 3. worker 지시와 결과

- 오케스트레이터·통합은 Claude 한 세션이 맡는다. 기능 구현·분석·시험은 Claude가 Codex CLI로 띄우는 일회성 worker가 맡고 완료 후 종료한다. 기존 Codex Root/Test/기능 세션은 재개해서 이어 쓰지 않고 ID 참고용으로만 보존한다.
- Claude는 매일 시작할 때 사용량을 한 번 확인해 구현 참여를 결정한다. 사용량 여유가 크면 worker와 겹치지 않는 파일을 직접 구현할 수 있다.
- worker 한 번의 범위는 막힘 하나의 원인 확인·연결 수정·1회 실행이다. 작은 오류는 내부에서 해결하며 다음 기능을 스스로 찾지 않는다. 실제 게임·포트 실행은 일회성 시험 worker 하나에 모은다.
- 지시문은 1~2쪽으로 목표 연결, 기준 소스·관련 파일·증거 위치, 확인 사실, 미확정, 쓰기 범위, 값 생산자·소비자, 완료 조건을 준다. 막히면 무엇이 없고 누가 만들며 어떤 최소 관측이 필요한지 남기게 한다.
- 과거 대화·28MB 기록·다른 기능 이력·무관 규칙·전수검증·장문 보고·끝없는 후속 지시를 worker 입력에 싣지 않는다. 필요한 기존 HANDOFF/API와 증거 위치를 준다.
- 결과는 한 화면 요약과 파일 위치로 끝낸다. 연결된 행동·실행 결과·첫 실패 또는 미확정·변경 파일·다음에 필요한 입력을 담는다. 별도 증거 보고서·ACK 체계를 만들지 않는다.
- 한 파일 한 writer를 지킨다. 범위·소유 파일이 겹치지 않는 현재 마일스톤 독립 작업만 병렬로 진행한다. 기존 기능 ID·소유 경로·공용 파일·실행·포트 소유권을 보존하고 writer를 바꿀 때 기존 writer를 해제한다.
- worker 모델은 `gpt-6.1-sol`을 명시하고 작업별 기존 실설정과 사용자 지정을 따른다. 메인 모델·effort를 임의 변경하지 않는다. 지정된 전문 모델은 일반 worker로 임의 대체하지 않는다.

## 4. 검증과 검토

검증은 원본·저장 손상 방지와 실제 동작 1회 실행 두 가지에 둔다. 새 검사기·guard·중복 확인·해시 전수 대조·증거 보고서를 만들지 않고 기존 검사를 늘리지 않는다.

Claude는 평소 전체 diff를 읽지 않고 실행 결과·worker 요약·변경 파일을 확인한다. 실패했거나 저장 형식·삭제·원본을 건드릴 때만 해당 diff 또는 독립 리뷰를 확인한다. 다중 검토·검토 계층·전수검증을 선행하지 않는다. 같은 소스의 재현·환경 분리·성능 재시험은 허용하고 모든 결과를 보존한다. 정식 PASS의 실제 순서와 정확한 소스 조합·시작 저장 경계는 유지한다.

## 5. 통합과 공식 큐

- Claude 한 세션이 우선순위·통합·선정·발주를 맡는다. 별도 Codex Root·상시 Test·기능 세션이나 세션 간 통지·ACK 체계를 운영하지 않는다.
- [공식 큐](INTEGRATION_QUEUE.json)와 기존 결과는 보존한다. 현재 마일스톤에 바로 쓸 준비 항목만 발주한다. 다른 기능·전기능 공통판·미준비 시나리오는 현재 마일스톤의 gate가 아니다.
- 큐 등록·선택·완료는 기존 `tools/integration_queue.py`와 [사용법](INTEGRATION_QUEUE_USAGE.md)을 쓴다. JSON 직접 수정·중복 큐·개별 요청 체계를 만들지 않는다. 기존 짧은 OS 잠금·같은 디렉터리 원자적 교체를 유지하고 통합·시험 동안 잠그지 않는다.
- 완결 구현은 `integration`, 마감 시험은 `test_result`로 남긴다. ID·기능·담당·요약·부모·변경분·근거 경로·준비 여부만 넣고 상세는 기존 결과 위치에 둔다. 등록은 권한·준비 성공·완료 증거가 아니다.
- 소스·실제 입력·시나리오·시작 저장이 준비돼야 `test_ready:true`다. 미준비 접점은 false로 두고 부족한 입력을 적는다. 기존 공용 packet-test-client/API·통과 flow를 재사용한다.
- 부모 참조와 자기 변경 파일을 통합하고 후보 전체를 덮어쓰지 않는다. 시험에 선정한 소스 조합은 FIRST/close까지 고정한다. 독립 파일 구현은 계속할 수 있다.
- 같은 ID를 다른 내용으로 덮지 않는다. 수정본은 `enqueue --supersedes <구ID>`, 등록된 대체 항목은 `supersede <구ID> --by <대체> --reason <근거>`, 잘못 닫은 항목은 `restore`의 기존 방식을 따른다. 원근거·실패·partial은 보존한다.
- 발주한 소스·해시는 고정하고 새 사본·출력은 실행 인수에 둔다. 메타데이터 불일치와 실제 소스 변경은 구분해 남기며 삭제·자동 성공으로 처리하지 않는다.
- 실패·미준비는 해당 경로만 멈춘다. 부족한 입력·생산자·필요 관측을 남기고 현재 마일스톤 안의 다른 독립 준비 작업을 계속한다. 큐·결과 도착만으로 새 권한·재개를 만들지 않는다.

## 6. 중지·재개와 인계

- 명시 중지 범위의 새 구현·분석·배정·병합·다음 큐·시험·재시도는 시작하지 않는다. 착수한 단위의 최소 마감·원 finally/FIRST close·원오류·partial/current·UIDburn 보존·소유 자원 정리·기존 인계만 끝낸다.
- 소스·결과·준비 완료·과거 재개 문구는 승인이 아니다. 사용자 명시 재개나 지정 조건의 실제 충족을 따른다. 일반 재개로 동결 기능·별도 승인 경계를 해제하지 않는다.
- 재개 때 Claude 한 세션과 새 일회성 worker 방식으로 이어간다. 기존 Codex 세션 ID는 소스·결과 위치를 찾는 참고로만 쓴다. 기능·소유권·실설정·정확 부모/변경분·성공과 실패·미완 계약·보존 상태·다음 행동을 승계한다.
- 세션 교체를 기능 재분할·전수검사·재승인·중복 발주·검증기 재작성의 이유로 삼지 않는다. 기존 ACTIVE/HANDOFF에서 현재 담당·수신처를 갱신하고 별도 registry나 사용자 표시 채팅을 만들지 않는다.

## 7. 조사·실패와 기록

### 막힌 계약과 전문 작업

- 분석이 필요하면 Claude가 막힌 계약을 일회성 분석 worker에 준다. 같은 대상의 기존 요약·함수 식별·필요 원문·지원되는 MCP 연결·Evidence·snapshot을 재사용한다. 과거 snapshot을 현재 실행의 증거로 쓰지 않는다.
- 바이너리 식별·도구·설정·함수 위치·채택 근거·미확정을 보존한다. 계약이 바뀌면 근거와 소비 코드를 함께 바꾸되 설명 변경만으로 해시 전수 대조나 연쇄 재검증을 하지 않는다.
- 원호출 전 실패는 객체·등록·소유·시점, callback 뒤 요청 부재는 선택·생성 조건, 서버 실패는 파싱·상태·응답·저장, 응답 뒤 실패는 실제 소비 경로를 중심으로 막힘 하나를 찾는다. 분류할 입력이 없으면 무엇이 없고 누가 생산하며 어떤 최소 관측이 필요한지 남긴다.
- 분석 도구 실패·시간초과를 제품 실패와 구분한다. 지원 도구·기존 대안을 쓰고 환경 전면 교체·주변 전체 해석·반복 상담을 선행하지 않는다. 답·근거·미확정·구현에 필요한 입력을 전달하면 해당 분석 worker를 종료한다.
- 실패 원문·COMMITTED/DRAINED/UNATTEMPTED·native pending·최신 POST·partial/current·UIDburn을 보존한다. 재BUY/learn/debit/cast·rollback·가짜 clean으로 기존 실패나 소진을 지우지 않는다.
- PAGE_NOACCESS·보안 전문 작업은 기존 Daybreak 담당·근거와 지정 모델 경계를 유지한다. 작업명에 ‘데이브레이크’를 넣고 코드·주소·신원·시점·보호 관측·실패·미확정·권한·거부 원문·소유 파일·산출물 위치를 준다. 기존 파일·실행 소유권까지 임의 이전하지 않는다.
- 지정 ‘6솔 데이브레이크’의 표시명·실제 ID·실제 선택을 확인할 수 없으면 알리고 배정하지 않는다. `gpt-daybreak-blue-latest`·일반 `gpt-6-sol`로 대체하거나 접근 제한·거부·승인 경계를 우회하지 않는다.

### 상태와 결과 기록

- ACTIVE_TASK는 현재 상태를 두고 마감 상세는 기존 월별 기록·HANDOFF·실행 결과에 둔다. 목표·현재 소스 조합·시작 저장·실제 연결 단계·첫 실패·부족 입력·변경 파일·다음을 해당 항목에 고쳐 쓴다. 날짜별 장문을 앞에 쌓지 않는다.
- worker 결과는 한 화면 요약과 파일 위치로 전달한다. 기존 실행 원문을 보존하고 중복 상태·증거 보고서·승인 체계를 만들지 않는다.
- 새 사용자 지시는 AGENTS·WORK_RULES의 해당 문장을 직접 수정하고 날짜·원문은 기존 RULES_CHANGELOG에 남긴다. 현재 작업에 미치는 영향은 ACTIVE에 반영한다.
- 시작 때 현재 상태는 ACTIVE를 읽고 월별 로그·아카이브·다른 기능 이력은 필요한 부분만 찾는다. 담당·권한이 불명확하면 막힌 행동과 필요한 결정을 남기며 독립 작업은 계속한다.

## 8. 파일 관리

- 새 vN 폴더를 늘리지 말고 같은 폴더를 수정한다. 기존 manifest·해시로 소스를 식별하고 부모 경로·해시·변경 파일을 보관한다. 동일 내용의 전체 부모/후보 복사를 늘리지 않는다. 입력이 없으면 새 버전 대신 첫 실패·부족 입력·최소 관측을 남긴다.
- 원본·불변 소스·사용자 저장·채택 근거·실패 원문·partial·UIDburn·기존 결과는 보존한다. 시험 출력은 기존 `work/local_original_session/runs/` 경로를 쓴다. 재시험 결과도 모두 보존한다.
- 상위 폴더를 향한 프로젝트 내부 junction은 만들지 않는다. 타 파일·원본·dirty 변경을 임의 commit·삭제·이동하지 않는다. Windows 재귀 삭제·이동은 실제 권한과 대상 절대 경로 경계를 지킨다.
- 규칙은 해당 주제 문장에 직접 반영하며 WORK_RULES는 27,000바이트 이내로 정리한다. 과거 규칙은 [원본](history/WORK_RULES_ARCHIVE_20261026.md)에 보존하고 현재 방식과 충돌하는 과거 절차를 다시 적용하지 않는다.
