# 새 소스 게임 구현을 계속하는 기준

2026-10-09. 최소 실제 마우스 시험 통과 뒤에도 구현을 계속하라는 사용자의 정정을 반영한다. [현재 상태](ACTIVE_TASK.md)가 최신 승인·현황의 기준이다. 메인 세션은 검토·통합을 맡고 GPT-6.1 Sol 워커가 구현한다.

## 진행 중인 연결 작업

- 현재 인증 자산108개를 그대로 읽어4청크128×128지역을 실제 앱에서 사용한다. 이전33×33 고정 장면 시험은 명시한 legacy 옵션으로 보존한다.
- 추적 카메라가 이동 중 화면을 갱신하고, 마우스 클릭은 그때 렌더링된 카메라와 같은 변환으로 목표를 선택한다. 자산 밖 지역·타일 gate·경계 거절과 viewport 바닥 coverage를 확인한다. 카메라 정책은 새 소스 host의 정책이며 원작 전체 카메라 동등성으로 표시하지 않는다.
- 새 소스 앱만의 전용 프로필을 만든다. 현재 자산을 검증한 뒤 로드된 지도 셀·좌표·방향을 확인하고 복원한다. 이동이 완료된 위치를 기록하며 현재 진행 중인 route나 animation은 저장하지 않는다. 기존 원본 저장·슬롯과 이전 시험 store는 수정하지 않는다.
- 프로필은 새로 만든 Store UUID와 자산 identity에 묶고, 소유 metadata 없는 기존 폴더를 채택하지 않는다. checkpoint가 늘어나면 새 segment와 binding을 게시해 이전 세대를 보존한다. 동시 두 번째 writer·잘못된 자산·손상·누락·쓰기 실패는 명시적으로 거절한다.
- 일반GUI 실행은 종료할 때까지 유지한다. 시험용 명시 시간 제한과 bounded headless 경로를 구분한다. 저장 실패 때는 사용자에게 보이는 상태를 표시하고 이동을 중단해 실패를 숨기지 않는다.

## 검토와 실제 확인

동일 production Scene/Runtime을 재빌드한다. 독립 raw S32 graph로8방향과 청크 경계 경로를 확인하고, 카메라 이동 중 클릭·지도 coverage·저장 후 새프로세스 복원·오류 거절을 검사한다. 워커 보고만으로 완료하지 않고 Root가 실제 결과와 코드를 검토한다.

최신 사용자 지시는 컴퓨터를 사용하므로 다시 말할 때까지 백그라운드 검증만 수행하라는 것이다. 새 GUI 창·마우스·키보드·OS 입력은 재허가 전 실행하지 않으며, 이전 idle 승인은 현재 실행 근거로 사용하지 않는다. 코드/native/headless/로컬 framebuffer 검증은 계속하고 새 제품 GUI 검증은 pending으로 기록한다. 원본/보관/저장 보존핀·현재 자산 해시와 소유 프로세스 상태도 확인한다.

## 이어서 닫을 범위

현재 전투·NPC·아이템·전체UI는 완성되지 않았다. 기존 현재NPC/item/spell 데이터와 원본 consumer·SPR·CSB 연결 근거를 다음 구현에 사용한다. 불명확한 서버 피해/명중 수치나 원작 camera/anchor/Nav를 임의의 원작 규칙으로 표시하지 않는다. 필요한 자료 조사와 근거를 확보할 수 있는 구현은 계속 진행한다. 최소 기능 시험을 전체 프로젝트 종료로 취급하지 않는다.
