# 클라이언트 이동·공격 속도와 동작 프레임 조사

2026-10-09. **클라이언트에 관련 데이터와 실제 시간 계산 코드가 있다.** `spell.bin`의 마법 피해 공식 조사와 별도로, `data/list.spr`에는 걷기·맨손/무기별 공격·방향/무방향 마법 시전의 동작 단계와 시간 가중치가 있다. 현재 원본 정적 코드에서 그 숫자를 시간으로 소비하는 경로까지 확인했다.

아래 시간은 **기본 속도 24, Actor의 재생 속도 2배 플래그 꺼짐, 외부 속도 보정값 0**을 가정한 한 동작의 명목 시간이다. 실제 화면 재생 측정값·서버가 허용하는 공격/이동 간격·명중 시점으로 확대하지 않는다.

또한 정상 동일 sprite 경로, 유효한 단계와 양수 C 합, 공격 진행 gate 활성, 특수 동작 경로가 아닌 상태를 전제한다. 초기값 24를 확인했으나 모든 sprite의 실제 런타임 재생률이 24임을 증명한 것은 아니다. 조건 밖의 상태는 미확정으로 유지한다.

## 직접 확인한 표본

현재 평문 `work/local_resource_provider/assets/data/list.spr`은 971,536B, SHA-256 `a3e184ed84af2b1e7d429461c555b281aaf9d8858cdced22b9dd0d708921fa44`이다. 이전 catalog와 일치하는 이미 확보한 26.09.29.2001 자료를 읽었다. 10월 9일 최신 배포 파일을 새로 다운로드한 결과는 아니다.

명칭은 SPR 헤더와 동작 이름이다. 현재 플레이어가 클래스·변신·무기에 따라 실제로 이 엔티티를 선택했음을 런타임에서 확인한 표가 아니다. 0시간 스텝·반복 스텝도 있어 단계 수를 고유 이미지 수, 화면에 실제로 표시된 프레임 수, 서버 공격 판정 수와 같게 보지 않는다. SPX 내부에 B번째 프레임이 실제 존재하는지는 별도 픽셀 해석 작업이다.

원문 예시는 `0.walk(1 4,0.0:4 0.1:4<300 0.2:4 0.3:4)`이다. `A.B:C`는 순서 있는 한 단계이며 C는 그 단계의 시간 가중치이다. 걷기의 네 단계에서 C가 각각 4이므로 합은 16이다. 기본값 24일 때 한 단계는 `4/24`초, 동작 전체는 `16/24`초가 된다.

`**N**`이 양수이면 C 합으로부터 재생률을 `C합/N*1000`으로 설정한다. 각 단계의 C를 그 재생률로 나누므로 전체 명목 시간은 `N/1000`초가 된다. **같은 6단계라도 652ms 또는 742ms가 될 수 있고, C 합이 달라도 같은 지정 시간으로 재생될 수 있다.** 원본은 float 계산이므로 표는 명목값/반올림값이다.

## 현재 원본 소비 코드의 근거

CONTROL SHA `9ffc24fe304aacbb98642363f7b19fd4610b12d1fd0cb09a30c0c944f170b7af`에 묶인 복원 코드만 읽었다. RVA는 정적 이미지 상대 주소이며 실행 중 프로세스 주소가 아니다.

- `347F50`의 실제 SPR 파서: `34804A`에서 문자열 `**`를 비교하고 숫자를 읽어 액션 `+0C`에 보존한다. `3484C7..3484EF`에서는 A/B/C를 읽어 단계 `+00/+04/+08`에 저장한다. `90F90`이 이 구조와 지정 시간을 런타임 액션 구조에 복사한다.
- `346EF0`의 초기화 `346FAE`는 sprite 구조 `+90`에 24를 설정하며 `347D80`이 같은 필드를 복사한다. 액션 Start `8F9A0`은 `8FB7F`에서 이를 기본 재생률로 읽는다.
- `8FB5E`는 각 단계 C를 합산한다. `8FB8B..8FBB8`에서 지정 시간 `+0C>0`이면 재생률을 `C합/N*1000.0`으로 바꾼다. 상수 RVA `126EC60`의 double 1000.0도 직접 검증했다.
- `90DA0`과 이어지는 코드 `90E12..90E26`은 선택한 단계의 C를 액션 재생률 `+28`로 나누어 단계 시간을 반환한다. 다른 분기·종료 조건은 표의 단순 합산보다 복잡하므로 표를 모든 상태의 실제 실행 시간으로 주장하지 않는다.
- RTTI로 확인한 `AttackAction` vtable `1180B78`: Start `91870`은 공통 `8F9A0`으로 점프하고 시간 소비 `91880`은 `90DA0`의 결과를 속도 getter의 축 1 값에 1을 더한 값으로 나눈다. `MovingAction` vtable `1180CA8`: Start `94570`도 공통 경로에 연결되며 시간 소비 `949D0`은 축 0을 사용한다. 이동·공격에 별도 보정축이 있다는 직접 코드 근거다. 이 getter 값의 정상 서버 입력·헤이스트/용기 중첩 배율은 이번 조사에서 닫지 않았다.
- 공통 Start에는 Actor `+4D` 플래그가 켜지면 재생률을 2배로 바꾸는 `8FBFC..8FC0E` 분기도 있다. 플래그의 정상 설정 의미·현재 실제값은 미확정이다. 위 표는 이 분기가 적용되지 않는 기준이다.
- 파서는 `!`를 단계 플래그로 저장하고 `AttackAction` NextFrame `913C0`의 `91446`이 그 비트를 검사한다. 공격 재생의 특수 처리 표식으로 연결되지만 서버 명중·대미지 판정 시점을 증명한 것은 아니다.

함수·범위·각 명령 바이트 SHA, RTTI/vtable, 상수, 입력 전후 핀은 [정적 코드 자료](../work/client_speed_research/code/)에 있다. 예전 스프라이트 파일 연결 조사에서 미확정이던 C와 `**N**`의 의미를 현재 원본 소비 코드로 추가 확인했다. 이전 보고서의 당시 미확정 문구는 조사 이력이다.

## 다른 테이블에 있는 속도 관련 정보

`spell_list.jsonc`에는 실제 delay 값 49개가 있다. 슬로우 ID28=500, 콜 라이트닝 ID33=150, 쇼크 스턴 ID86=8000 등이다. 이 필드의 소비 코드·시간 단위·평타/시전/재사용 간격과의 관계는 이번에 확인하지 않았으므로 SPR 시간 계산과 합치지 않는다.

`behavior_list.jsonc`는 Loot `_delay=600`을 사용하며 주석으로 600=0.6초를 설명한다. 이 주석은 해당 행동 지연에 대한 단위 근거다. 다른 파일의 delay 필드에 그대로 적용하지 않는다.

마법 설명에는 헤이스트 이동·공격 가속 1,200초, 그레이터 헤이스트 2,400초, 홀리 워크 이동 가속 64초, 윈드 워크 이동 가속 1,200초 등이 있다. 지속 시간과 효과 축은 명시되어 있으나 속도 배율은 없다.

`desctoken.bin`에는 `attackSpeedBonus`, `moveSpeedBonus`, `spellSpeedBonus`, `frame`, `haste` 등의 이름이 있다. 사전 ID는 속도 수치가 아니다. 현재 19개 binary를 다시 읽고 named 속성 483개, 아이템 표시 속성 5,968개, 제작 표시 속성 1,712개를 검사했을 때 이 명시적 경로의 속도/프레임 보정값은 0개였다. 이름 없는 binary 숫자 필드·네트워크 상태에도 속도가 없다는 뜻은 아니다. ## 서버 룰에 활용할 범위와 검증

SPR 엔티티·무기 동작별 기본 시간표, 지정 시간 override, 단계별 가중치와 재생 이벤트 표식은 서버 룰을 복원하거나 로컬 클라이언트 재생을 구현하는 구체적인 입력이 된다. 최종 서버 간격은 실제 선택되는 sprite/action, 이동·공격 보정값, 플래그, 네트워크 시간 정책과 연결해야 한다. 이번 조사에서 룰을 런타임 서버에 적용하거나 공격/이동을 실제 실행하지 않았다.

현재 2,976개 SPR 정의/10,664개 액션/77,097개 strict 토큰과 구버전 2,693개 정의/9,497개 액션/67,310개 토큰을 다시 계산했다. 두 버전 모두 `#2332 death`의 `40.10.:4` 한 항목은 strict 문법 밖이므로 원문을 보존하며 원본 결함으로 단정하지 않는다.

Root는 원문 표본·전체 개수·입력 SHA, 정적 코드 범위와 명령 바이트·상수·RTTI/COL/vtable 및 직접 점프를 독립 대조했다. 13,109개 검사 PASS, 69개 JSON parse PASS이며 결과는 [root-review.json](../work/client_speed_research/root-review.json), 계산 표본은 [nominal-timings.json](../work/client_speed_research/nominal-timings.json)에 있다. 원본·보관·SDK·팩·키 변경, 게임 실행·메모리 읽기·UAC는 없었다.

비교 자료로 [L1J 자체 공개 SprTable 소스](https://github.com/l1j-en/classic/blob/103e6f6c9dd83545959d8e87d3f59f8de1f40ef0/src/l1j/server/server/datatables/SprTable.java#L150)도 확인했다. 해당 구현은 별도 DB의 framecount/framerate로 시간을 계산하며 40이라는 계수를 쓴다. **위 표는 L1J 식을 가져온 것이 아니라 현재 NC 클라이언트 자체 코드로 계산했다.** L1J 값은 현행 NC 서버 공식 증거로 채택하지 않았다.
